# Provider verification and recovery

CLI forms checked against the installed `--help` on 2026-09-14. Recheck unsupported flags instead of substituting permission bypasses. Execute in the selected project directory; use a new session, not continue/resume. The helper builds argument arrays, bounds runtime, kills the timed-out process group and records metadata without raw provider output.

| Provider | Command shape | Limit |
| --- | --- | --- |
| Claude Code | `claude -p --permission-mode plan --tools Read,Glob,Grep --strict-mcp-config --mcp-config '{"mcpServers":{}}' --no-session-persistence --output-format json PROMPT` | Only read tools exposed; MCP disabled for this probe. User startup hooks may still apply. Does not verify hook enforcement or MCP integrations. |
| Codex | `codex exec --sandbox read-only --skip-git-repo-check --ephemeral --color never PROMPT` | Read-only shell sandbox; configured integrations/hooks have their own behavior. This is not proof of universal no-side-effects. |
| agy | `agy --mode plan --sandbox --add-dir PROJECT --print-timeout TIMEOUT-10s --output-format json --print PROMPT` | CLI advertises planning plus terminal restrictions; their coverage is not independently proven. Prefer an isolated fixture until that is measured. Never use dangerously-skip-permissions. **`--add-dir` is required**: measured 2026-09-14, agy does not take its workspace from the working directory — without it the run reports an empty workspace root and can answer from earlier session context instead of the probed project. Its `--print-timeout` is set just under the helper timeout so a slow run still returns a parseable envelope. |

`verify --tool claude|codex|agy --expect PHRASE --timeout 90` uses the same probe intent for all three. It asks for the applicable instruction sources, a labelled `Setup verification phrase` and the exact YAML description of nathan-setup. Use `--question` to ask about an existing real project rule, with `--expect` containing its exact answer; there is no need to add a verification marker to a real project. The expected phrase and skill description are checked locally, not supplied in the prompt. Readable evidence is returned for the caller to review; success requires structured fields for the phrase, actual description, resolved installed entry, four steps, availability and an empty conflict list; it only means this bounded discovery probe passed. If a real project's instructions have no labelled verification phrase, use a precise `--question` about an existing rule, or report pending/use an isolated fixture; do not falsely call a fixture pass a project pass. Authentication, unavailable CLI and timeouts stay pending. A successful CLI response with missing required evidence is failed. The prompt asks providers to use built-in read-only file tools rather than shell commands: measured 2026-09-14, agy auto-denies the `command` permission in headless mode (it cannot prompt) and then returns `status: SUCCESS` with an empty response and a `denied_actions` list. An empty response with denied actions is an environment gap and stays **pending** with the denied tool names in the reason, not failed evidence — a missing permission is not proof that discovery failed.

Sources:
- Codex instruction discovery: https://learn.chatgpt.com/docs/agent-configuration/agents-md — AGENTS.override.md, root-to-cwd discovery and profile/global configuration can affect effective instructions.
- Claude memory/imports: https://code.claude.com/docs/en/memory — CLAUDE.md and `@path` imports; additional local/ancestor instructions also matter. Import token detection accepts whitespace, list text and `@./AGENTS.md`, excludes fenced/commented examples and rejects filename prefixes. It is structural evidence, not the provider's parser.
- agy is Antigravity CLI. Nathan's maintained configuration uses AGENTS.md and `~/.gemini/config/skills`. Generic Gemini configuration is not an agy installation signal. `agy --help` alone cannot establish discovery.

Local `.nathan-setup/state.json` holds managed-block hashes, owned-link records and append-only probe metadata. A changed instruction fingerprint invalidates prior probe success. Missing/deleted state means unknown ownership and pending verification; it must not silently adopt or remove existing blocks. State locking serializes helper processes; full-file hash rechecks reduce accidental editor races but are not an OS-level compare-and-swap against arbitrary writers. Keep state private and untracked; clone/worktree migration requires new verification.

The source `scripts/relink.sh --list` is the canonical recursive skill catalog. It stops at each skill root and rejects duplicate skill names before linking. Both relink and setup use this list once per inventory.
